# ⏱ Хронос — Time Tracker

Тайм-трекер в духе Clockify с встроенным **Pomodoro**, проектами, отчётами,
командами и выгрузкой выполненных за день задач в **Excel**.
Интерфейс — редизайн «Хронос»: тёмная/светлая тема, командная палитра ⌘K,
горячие клавиши, фокус-режим.

**Стек:** NestJS + TypeScript + PostgreSQL + Sequelize (backend), Next.js +
TypeScript + CSS (frontend), Swagger (документация), Docker Compose.

> Все контракты API (поля запросов и ответов) — в **snake_case**
> (`access_token`, `started_at`, `task_id`, `estimated_minutes`, …).

## Возможности

- 🔐 **Авторизация** — регистрация/логин, JWT, данные изолированы по пользователю.
- ✅ **Задачи** — название, описание, статус (todo / in progress / done),
  плановое время выполнения (estimate).
- ⏱ **Учёт времени** — таймер start/stop (как в Clockify) **и** ручной ввод
  через два поля времени — «от» (`started_at`) и «до» (`ended_at`); длительность
  считается из разницы. У каждой задачи считается суммарное затреканное время.
- 🗂 **Проекты** — цвет, инлайн-переименование, архив (записи остаются в
  отчётах), статистика за неделю; задачи привязываются к проекту.
- 📈 **Отчёты** — бар-чарт за 7 дней с выбором дня, серия целей (streak),
  heatmap за 14 дней, разбивка по проектам и топ задач за неделю
  (один запрос `GET /time-entries/summary`).
- 😴 **Контроль простоя** — если таймер идёт, а активности нет дольше порога,
  предлагается «вычесть простой» (стоп с `ended_at` = момент последней
  активности).
- ⚙️ **Настройки пользователя** — цель дня, порог простоя, напоминания
  (Notification API), тема; хранятся на сервере + localStorage.
- 🍅 **Pomodoro** — настройки (длительность фокуса/перерывов, цикл до длинного
  перерыва, авто-старт) хранятся на сервере; завершённые сессии записываются и
  привязываются к задачам; есть статистика за день; опционально фокус-сессии
  записываются в трекер времени; мини-виджет в сайдбаре.
- 👥 **Команда (workspaces)** — участники с ролями
  (владелец/админ/менеджер/участник/клиент), приглашения по email (письмо)
  и по ссылке, live-статус «кто что трекает», «не беспокоить» во время
  фокус-сессии, мини-дашборд (кто трекает/недобор/перегруз), загрузка недели,
  журнал действий (аудит-лог), смена ролей владельцем, отделы с фильтром,
  профиль сотрудника (оплата почасовая/оклад, отдел, отпуска и больничные,
  открытые задачи).
- 🏢 **Несколько компаний на аккаунт** — переключатель в сайдбаре, мастер
  создания (название → отделы → приглашения), данные компаний изолированы
  (`workspace_id` у проектов, задач и записей времени). Компания: логотип,
  фирменный цвет, валюта (RUB/USD/EUR/KZT/UZS), норма часов в день,
  округление времени до 15/30 минут для клиентских отчётов и счетов.
- 🔐 **RBAC** — участник видит только свои задачи и отчёты; админ назначает
  задачи (исполнитель), видит всю команду, отчёты по участникам и деньги;
  менеджер — только свой проект без денег; клиент — только отчёты read-only.
- 🧾 **Аккаунт** — фото профиля (client-side crop, инициалы по умолчанию),
  смена имени/email (сброс верификации), верификация почты письмом
  (токен, TTL 24ч), смена пароля, 2FA (TOTP, QR), список активных сессий
  и устройств с «Выйти» / «Выйти везде», экспорт всех данных (GDPR),
  удаление аккаунта с подтверждением вводом email.
- 🔑 **Auth 2.0** — вход по одноразовой ссылке из письма (magic link, TTL
  15 мин), сброс пароля письмом (TTL 1ч, отзывает прежние сессии), капча
  после 2 неудачных попыток, rate-limit на `/auth/*`.
- ✅ **Задачи++** — исполнитель, приоритет (высокий/средний/низкий), дедлайн,
  баннер «Просрочено: N задач», «Мои задачи на сегодня» в Трекере, шаблоны
  задач (чипы + «В шаблон»), виды **Список / Канбан** (перенос стрелками)
  и групповые действия по чекбоксам («Выбрано: N» → В работу / Готово /
  Удалить).
- 💰 **Деньги** — ставка и недельный бюджет часов у проекта, персональная
  ставка сотрудника (почасовая или оклад — пересчитывается по норме и
  перекрывает проектную), billable-флаг (тумблер ₽) и комментарий у записи,
  суммы в отчётах в валюте компании, превью счёта (billable-часы × ставка
  с округлением) и печать в PDF.
- 🎯 **Вехи проекта и клиентская петля** — редактор вех (план → в работе →
  готово) в «Проектах»; у роли «Клиент» — дашборд с бюджетом этапа и
  прогнозом даты, вехами, лентой недели и тредом «Вопросы по отчёту».
- 📋 **Таймшиты** — участник отправляет неделю на проверку (прикладывается
  авто-сводка); админ утверждает или возвращает **только с причиной**
  (чипы частых причин + текст → письмо, уведомление, аудит и красная плашка
  в Трекере с кнопкой «Исправить»); массовое утверждение; утверждённая
  неделя блокирует записи.
- 🔗 **Публичная ссылка на отчёт** — токен-страница `/r/<token>` c опциями
  «скрыть суммы/имена» и выключателем.
- 🔔 **Уведомления** — отдельный экран с фильтрами (Все / Непрочитанные /
  Таймшиты / Задачи), типом, каналами доставки и кнопкой действия; матрица
  каналов **Email / Пуш / В кабинете** по каждому событию в настройках;
  веб-пуши (VAPID, service worker) с карточкой статуса разрешения;
  колокольчик в шапке — быстрый доступ.
- ⚡ **Генератор текстов** — стендап-отчёт («вчера → сегодня» /
  «сегодня → завтра») из записей и задач: ссылки на задачи (`external_url`),
  строка активностей, отработано/осталось часов к месячному лимиту,
  редактируемый текст, копирование в один клик, отправка в Slack/Telegram
  (демо); свой шаблон (приветствие/активности/подпись) в Настройках и
  авто-отправка в 10:00 (cron); AI-сводка по задачам через Claude API
  (без ключа — фолбэк «задача — часы»). Плюс «Отчёт для клиента (текст)»
  за неделю по проекту с часами и суммой, «Сводка команды за вчера» для
  админа и Release notes из задач «Готово»; авто-сводка недели
  прикладывается к таймшиту при отправке; пункт «Стендап-отчёт» в ⌘K.
- 🧭 **Onboarding** — тур из 3 шагов + чек-лист «Первые шаги»; undo при
  удалении; drag-редактирование записей на таймлайне; «забытый таймер»
  (баннер после 4ч) и авто-стоп в 19:00; оффлайн-индикатор; поиск по истории
  в ⌘K; мобильный режим (сайдбар-шторка).
- ⌨️ **Палитра ⌘K и горячие клавиши** — запуск таймера по тексту, старт задачи,
  создание задачи, навигация, тема; `S` стоп/продолжить, `N` новая задача,
  `F` фокус-режим, `T` тема, `1–7` экраны, `?` справка (учтена русская
  раскладка).
- 📊 **Экспорт в Excel** — `.xlsx` с тремя листами: *Completed Tasks*,
  *Time Entries*, *Summary* за выбранный день (по умолчанию — сегодня).
- 🧩 **Записи времени** — инлайн-правка времени, комментарий, ✂ разрезание
  записи пополам, drag краёв на таймлайне, undo при удалении; сервер не даёт
  записям пересекаться по времени, а старт/стоп таймера идемпотентны
  (двойной клик и ретрай после потери сети не плодят записей).
- 📥 **Импорт и демо-данные** — CSV-экспорт Toggl Track, Clockify и Harvest
  разбирается автоматически (проекты, задачи, интервалы; часы в форматах
  `1:30:00` и `1.5`); кнопка «Заполнить примером» в чек-листе создаёт
  демо-проект, задачи и записи, чтобы новая компания увидела живые экраны.
- 📖 **База знаний** — постоянный раздел в сайдбаре для всех ролей
  (начало работы, фреймворк дня, роли, разделы, хоткеи, FAQ).
- 🛬 **Лендинг** — публичная главная (продукт бесплатный, без тарифов),
  единый SVG-знак «Хронос» в интерфейсе, письмах, favicon и OG-превью.
- 📚 **Swagger** — интерактивная документация API.

## Быстрый старт (Docker Compose)

Требуется только Docker.

```bash
cp .env.example .env          # при необходимости поменяйте секреты
docker compose up --build
```

После запуска:

| Сервис            | URL                                |
| ----------------- | ---------------------------------- |
| Frontend          | http://localhost:3000              |
| Backend API       | http://localhost:3001/api          |
| Swagger           | http://localhost:3001/api/docs     |
| PostgreSQL        | localhost:5433 (в контейнере 5432) |

Откройте http://localhost:3000, зарегистрируйтесь и начинайте трекать время.

## Локальный запуск (без Docker)

Нужен Node.js 18+ и работающий PostgreSQL.

**1. База данных**

```bash
createdb time_tracker
```

> UUID генерируются на стороне Node (Sequelize `UUIDV4`), расширения Postgres
> не требуются.

**2. Backend**

```bash
cd backend
cp .env.example .env          # пропишите доступы к вашей БД
npm install
npm run start:dev             # http://localhost:3001/api
```

**3. Frontend**

```bash
cd frontend
cp .env.example .env.local    # NEXT_PUBLIC_API_URL=http://localhost:3001/api
npm install
npm run dev                   # http://localhost:3000
```

### Письма и env

Письма уходят через SMTP (`SMTP_HOST`, `SMTP_PORT`, `SMTP_USER`,
`SMTP_PASS`, `MAIL_FROM`); без настройки SMTP они логируются в консоль
сервера (dev-режим). `FRONTEND_URL` — база для ссылок в письмах
(по умолчанию `http://localhost:3000`).

Реализованы все 7 писем из `Emails.dc.html`: верификация почты,
приглашение в команду, welcome после создания компании, «вам назначена
задача», «таймшит возвращён» (с цитатой причины), дайджест недели
(понедельник, 09:00 — уважает матрицу каналов) и сброс пароля
(с устройством запроса); плюс письмо magic-link для входа без пароля.

Веб-пуши включаются парой VAPID-ключей (`VAPID_PUBLIC_KEY`,
`VAPID_PRIVATE_KEY`, `VAPID_SUBJECT`) — сгенерировать можно командой
`npx web-push generate-vapid-keys`. Без них колонка «Пуш» в матрице
уведомлений недоступна, остальные каналы работают.

`ANTHROPIC_API_KEY` (опционально) включает AI-сводку в стендап-отчёте —
одна строка на задачу через Claude API (модель `claude-opus-5`); без ключа
используется фолбэк «задача — часы». Cron-задачи (`@nestjs/schedule`,
серверное время): будни 09:30 — напоминание про стендап в центр
уведомлений; будни 10:00 — авто-генерация стендапа для пользователей с
включённой авто-отправкой.

Доставка в Slack/Telegram (кнопки «→ Slack»/«→ Telegram» и авто-отправка)
идёт через вебхуки: `SLACK_WEBHOOK_URL` (incoming webhook) и
`TELEGRAM_BOT_TOKEN` + `TELEGRAM_CHAT_ID` (Bot API `sendMessage`).
Без этих переменных отправка работает в демо-режиме (`sent: false`).

## Заметки по реализации

- Запуск нового таймера автоматически останавливает текущий (поведение Clockify).
- «Сегодня» в выгрузке/статистике считается по календарному дню в **UTC**
  (можно указать конкретный день параметром `?date=YYYY-MM-DD`).
- Pomodoro-таймер тикает на клиенте; на сервере хранятся настройки и
  завершённые сессии (как и было согласовано).
- Данные компаний изолированы: `projects`, `tasks` и `time_entries` несут
  `workspace_id`, все выборки скоупятся по активной компании (записи,
  созданные до мультитенантности, остаются видны их авторам).
- TOTP для 2FA считается на `node:crypto` (RFC 6238) — без внешних
  зависимостей.
- Rate-limit: `@nestjs/throttler`, отдельные лимиты на `/auth/*`.
- ORM — **Sequelize** (`sequelize-typescript` + `@nestjs/sequelize`),
  запускается с `synchronize: true` + `sync: { alter: true }` — схема
  создаётся и дополняется автоматически.
  Для production рекомендуется перейти на миграции (`sequelize-cli`).
- Дизайн-референс редизайна — в `design_handoff_chronos_redesign/`
  (HTML-прототип, скриншоты, ТЗ).
- Контракты API — в snake_case; внутренние модели и атрибуты тоже названы в
  snake_case, чтобы JSON отдавался без дополнительной трансформации.
